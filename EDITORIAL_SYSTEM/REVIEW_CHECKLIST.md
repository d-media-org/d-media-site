# Review Checklist 1.0

## Purpose

Този документ е окончателният редакторски контрол за блог статии на `d . media`.

DMA няма право да счита статия за готова при нито един FAIL.

Ако който и да е оценъчен критерий е под 9/10, статията се връща за редакция.

## PASS / FAIL Checklist

Всеки критерий се маркира с PASS или FAIL.

### Content

- PASS / FAIL: Статията започва с реален проблем.
- PASS / FAIL: Текстът не се отклонява от темата след първите 2–3 абзаца.
- PASS / FAIL: Няма маркетингов пълнеж.
- PASS / FAIL: Всеки абзац добавя нова информация.

### Topic Focus

- PASS / FAIL: H1 задава ясна тема.
- PASS / FAIL: Всяка секция служи на H1.
- PASS / FAIL: Няма странични теми, които не подкрепят основната линия.

### Logic

- PASS / FAIL: Секциите следват причинно-следствен ред.
- PASS / FAIL: Всеки следващ раздел надгражда предишния.
- PASS / FAIL: Две H2 секции не могат да бъдат разменени без загуба на логика.

### Structure

- PASS / FAIL: Има един H1.
- PASS / FAIL: H2 секциите са 6–12, освен ако темата обективно не изисква друго.
- PASS / FAIL: H3 се използва само при реална нужда.

### Information Architecture

- PASS / FAIL: Статията следва логиката Проблем → Причина → Механизъм → Пример → Грешки → Практики → Checklist → FAQ → Заключение → CTA.
- PASS / FAIL: Всяка H2 секция може да съществува като мини-статия.

### UX

- PASS / FAIL: Reading flow е ясен.
- PASS / FAIL: След всяка секция читателят има причина да продължи.
- PASS / FAIL: Няма секции, в които интересът рязко пада.

### UI

- PASS / FAIL: Има визуални паузи.
- PASS / FAIL: Няма екран само с голям блок текст.
- PASS / FAIL: Визуалните елементи помагат на разбирането.

### Reading Flow

- PASS / FAIL: Въведението води естествено към първата H2 секция.
- PASS / FAIL: Заключението не въвежда нова тема.

### Reading Journey

- PASS / FAIL: Читателят преминава от проблем към решение.
- PASS / FAIL: CTA идва след достатъчно контекст.

### Visual Hierarchy

- PASS / FAIL: H2 заглавията са ясни при сканиране.
- PASS / FAIL: Списъци, таблици и callout-и не се използват декоративно.

### Visual Rhythm

- PASS / FAIL: Има редуване на текст, списъци, примери и визуални блокове.
- PASS / FAIL: Няма монотонна поредица от дълги абзаци.

### White Space

- PASS / FAIL: Текстът има достатъчно въздух.
- PASS / FAIL: White space не прикрива слабо съдържание.

### Density

- PASS / FAIL: Информационната плътност е висока.
- PASS / FAIL: Няма изкуствено удължаване.

### Mobile UX

- PASS / FAIL: Абзаците са удобни за mobile четене.
- PASS / FAIL: Таблици и списъци са usable на mobile.

### Desktop UX

- PASS / FAIL: Дължината на реда е удобна.
- PASS / FAIL: Статията се сканира добре на desktop.

### Tablet UX

- PASS / FAIL: Визуалната структура остава четима.
- PASS / FAIL: Няма елементи, които доминират над текста.

### Scan Test

- PASS / FAIL: Само H2, списъци и callout-и дават ясна представа за статията.

### F-pattern

- PASS / FAIL: Началата на секциите са директни.
- PASS / FAIL: Важните думи не са скрити в края на дълги изречения.

### Navigation

- PASS / FAIL: Дългата статия има navigation или ясна вътрешна структура.
- PASS / FAIL: Читателят не се губи в текста.

### Internal Links

- PASS / FAIL: Линковете са естествени.
- PASS / FAIL: Няма link spam.
- PASS / FAIL: Anchor text е описателен.

### Related Articles

- PASS / FAIL: Свързаните статии са тематично близки.
- PASS / FAIL: Не са добавени случайни links.

### Related Services

- PASS / FAIL: Услугите са свързани само когато има реална връзка.

### Examples

- PASS / FAIL: Има минимум 3 практически примера, освен ако темата обективно не го изключва.
- PASS / FAIL: Примерите са конкретни.

### Tables

- PASS / FAIL: Таблиците помагат за сравнение или структуриране.
- PASS / FAIL: Таблиците са четими на mobile.

### Images

- PASS / FAIL: Изображенията имат информационна стойност.
- PASS / FAIL: Използват съществуващия asset pipeline, когато са част от сайта.

### Videos

- PASS / FAIL: Всяко видео има thumbnail/poster.
- PASS / FAIL: Няма 404 за poster/video assets.

### FAQ

- PASS / FAIL: Има минимум 5 FAQ въпроса при дълга статия.
- PASS / FAIL: FAQ не повтаря механично основния текст.

### CTA

- PASS / FAIL: CTA е естествена следваща стъпка.
- PASS / FAIL: CTA не звучи като маркетингово прекъсване.

### Accessibility

- PASS / FAIL: Структурата е семантична.
- PASS / FAIL: Визуалните елементи не създават недостъпно съдържание.

### Readability

- PASS / FAIL: Езикът е естествен.
- PASS / FAIL: Няма излишни англицизми, освен технически идентификатори.

### SEO

- PASS / FAIL: Title, description, canonical и internal links са съгласувани с темата.
- PASS / FAIL: Няма keyword stuffing.

### GEO

- PASS / FAIL: Статията ясно дефинира entities, relationships и context.
- PASS / FAIL: Няма недоказуеми твърдения за AI цитиране.

### AI Readiness

- PASS / FAIL: Основният отговор е извличаем рано.
- PASS / FAIL: Структурата е ясна за ChatGPT, Gemini, Claude, Perplexity и AI Overview.

### Definition of Done

- PASS / FAIL: Няма FAIL в checklist-а.
- PASS / FAIL: Всички оценъчни критерии са 9/10 или повече.
- PASS / FAIL: DMA може да отговори `Да` на въпроса: „Ако публикувам това утре на началната страница на d . media, ще се гордея ли с него след една година?“

- Логическа последователност: __/10
- Практическа стойност: __/10
- UX: __/10
- UI: __/10
- Визуална структура: __/10
- Четимост: __/10
- GEO: __/10
- AI Readiness: __/10
- Готовност за публикуване: __/10

Ако която и да е оценка е под 9/10, статията се връща за редакция.

## Final Decision

Статус:

- PASS
- FAIL

При FAIL статията не се публикува и не се счита за завършена.
