# SOP-001 — Изпълнение на задача

## Цел

Тази процедура описва минималния работен ред за изпълнение на всяка бъдеща задача в репозиторията на `d . media`.

## 1. Зареждане на контекст

Преди работа задължително прочети проектния контекст:

- `AGENTS.md`
- `SOURCE_OF_TRUTH.md`
- `DMA.md`
- `OWNER_REQUIREMENTS.md`
- `CHECKLIST.md`
- `PROJECT.md`
- `KNOWLEDGE_BASE.md`
- `OPEN_QUESTIONS.md`
- `DECISIONS.md`
- `SITE_HISTORY.md`
- `SOP-001-EXECUTE_TASK.md`

`OWNER_REQUIREMENTS.md` е задължителен контекст за всяка задача. Ако задачата е тясно ограничена, не прави излишни промени, но не игнорирай правилата за обхват, език, Project Owner изисквания и финален отчет.

Допълнителен контекст според задачата:

- `EDITORIAL_SYSTEM/README.md` и свързаните editorial документи, когато задачата засяга блог статии.
- `SYSTEM_HISTORY.md`, когато задачата засяга AIOS, Automation, DMA, Editorial System или документационната архитектура.
- `README.md`, когато задачата е developer onboarding, local setup или command usage.

## 2. Анализ

Определи мислено:

- каква е целта;
- кои файлове могат да бъдат засегнати;
- кои файлове са изрично забранени;
- какъв е рискът: документация, съдържание, production код, SEO, API, accessibility, deploy;
- липсва ли информация;
- може ли задачата да се реши с по-малък diff.

Не започвай с дълъг план към потребителя, освен ако той изрично не поиска план.

## 3. Ако липсва информация

Ако липсва информация, която е необходима за безопасно изпълнение:

- задай един кратък въпрос;
- не предполагай;
- не измисляй факти;
- не попълвай бизнес, правни, SEO, pricing или ownership данни без доказателство.

Когато задачата изисква маркиране на несигурност, използвай:

```text
Нуждае се от потвърждение.
```

## 4. Изпълнение

Редактирай само необходимите файлове.

Забранено е:

- да правиш странични промени;
- да рефакторираш непоискан код;
- да променяш стил без задача;
- да променяш package/config/CI/CD/assets без изрично разрешение;
- да пипаш production код при документационна задача;
- да променяш предназначението на съществуващ файл.

При наличие на разрешен списък от файлове, работи само в него.

## 5. Проверка

Изпълни минималните релевантни проверки според вида задача.

За документационна задача:

- провери създадените или редактираните файлове;
- провери `git status --short`;
- потвърди, че промените са само в разрешения обхват.

За website/code задача, когато е приложимо:

- `npm run build`
- `npm run lint`
- type check, ако има отделна команда или е част от build процеса;
- `npm run astro:cf:validate`, ако задачата засяга Astro/Cloudflare output;
- визуална или route проверка, ако задачата засяга UI, navigation, responsive, SEO или public routes.

Ако проверка не е приложима или не може да бъде изпълнена, посочи това във финалния отчет.

## 6. Финален отчет

Финалният отчет винаги е на български и се дава като plain text, който може да бъде копиран наведнъж.

Задължителен формат:

```text
Какво е направено

Кратко описание.

Кои файлове са променени

file

Какво не е променено

Кратко описание на забранените или незасегнатите части.

Какво трябва да бъде проверено ръчно

Няма.
```

Ако има ръчни проверки, изброй само проверките, които не могат да бъдат автоматизирани.
